# ThaiRide — контекст проекта

Документ для того, кто подхватывает проект: что это, что решено, что сделано, что дальше.

## Идея

Мобильное приложение для Таиланда: карта, на которой пользователи отмечают полицейские
посты и проверки, подтверждают («Актуально») или опровергают («Неактуально») их.
Всё обновляется онлайн. Аудитория — в первую очередь туристы и экспаты на байках
и машинах (Пхукет, Паттайя, Самуи, Бангкок, Чиангмай), плюс местные.

Референс — российское приложение **Easy Ride**. Его путь пользователя скопирован почти 1:1:
- тёмная карта с пинами, внизу большая кнопка «Поставить метку»;
- режим постановки: карта двигается под прицелом, снизу панель — адрес (синяя плашка),
  комментарий до 280 символов, сетка типов, кнопки «←» и «Добавить метку»;
- ограничение «метка не дальше 70 км от себя»;
- карточка метки: тип (синяя шапка), комментарии, «N подтверждений, X мин назад»,
  адрес, кнопки «Актуально / Неактуально», «Поделиться».

Отличия от Easy Ride — типы меток под Таиланд и три языка.

## Решения, принятые с заказчиком

### Время жизни метки (согласовано)
- новая метка живёт **1 час**;
- каждое «Актуально» продлевает до **now() + 3 часа**;
- **2 разных** «Неактуально» после последнего подтверждения снимают метку досрочно;
- одно правило для всех типов (раздельного TTL по типам нет).

### Прочие правила (реализованы на сервере)
- метку можно поставить не дальше 70 км от текущего положения пользователя;
- не больше 5 меток за 10 минут от одного пользователя;
- голосовать за свою метку нельзя; повторный голос за ту же метку — не чаще раза в 15 минут;
- новая метка того же типа в радиусе 150 м от живой не создаётся — засчитывается
  как подтверждение существующей;
- комментарии: до 280 символов, не больше 10 за 10 минут;
- цвет пина: **красный** — подтверждали/создали меньше часа назад, **жёлтый** — давно.

### Типы меток
| ключ в БД | RU | смысл |
|---|---|---|
| `checkpoint` | Пост | стационарный пост (ด่าน) |
| `moto_patrol` | Мотопатруль | полиция на байках |
| `tourist_check` | Проверка туристов | права/IDP, шлем, документы на байк |
| `alcohol` | Алкотест | |
| `drug_test` | Тест на наркотики | пост с экспресс-тестом. Название намеренно нейтральное — не «наркорейд» — из-за правил Google Play / App Store |
| `highway` | Дорожная полиция | Highway Police, радары |
| `camera` | Камера | камера скорости |
| `hazard` | ДТП / опасность | авария, затопление, ремонт |

### Языки
Русский, английский, тайский. Выбор по языку системы, меняется в настройках.

### Пользователи
Без регистрации — анонимный вход Supabase (`signInAnonymously`). Пользователь = устройство.

## Стек

- **Flutter** (Android + iOS из одного кода). Flutter 3.47.7 / Dart 3.13.
- Карта: `flutter_map` + растровые тайлы **CARTO dark_all** (OpenStreetMap).
  Для продакшна с большой аудиторией тайлы нужно сменить на платный/свой источник
  (MapTiler, Stadia, self-hosted) — у CARTO ограничения на коммерческое использование.
- Геолокация: `geolocator`; обратное геокодирование (адрес): `geocoding` (нативный геокодер ОС).
- Сервер: **Supabase** (Postgres + Realtime + Auth). Вся бизнес-логика — в SQL-функциях.
- Прочее: `share_plus`, `shared_preferences`, `latlong2`.

## Инфраструктура

- Репозиторий: https://github.com/Vlad-AQA/Ride-s, ветка `main`.
- **GitHub Actions** (`.github/workflows/build-apk.yml`): на каждый пуш в `main` —
  `flutter analyze` и `flutter build apk --release`; APK в Artifacts → `thairide-apk`.
  Release подписан debug-ключом (для установки вручную годится, для Google Play — нет).
- **Supabase**: проект `gkzegtyeohhchiplnajn`, регион Tokyo (ap-northeast-1), тариф Free.
  - URL: `https://gkzegtyeohhchiplnajn.supabase.co`
  - publishable-ключ прописан в `lib/config.dart` (он публичный, это нормально).
  - Схема `supabase/schema.sql` применена через SQL Editor; анонимный вход включён.
  - Пароль БД и secret-ключ есть только у владельца, в репозитории их нет и быть не должно.
- applicationId / bundle: `app.thairide.thairide`, отображаемое имя «ThaiRide» (рабочее
  название, финальное не выбрано).

## Структура кода

```
lib/
  main.dart             запуск: сразу рисует экран загрузки (_Startup), затем init Supabase;
                        при ошибке показывает её текст и кнопку «Повторить»
  config.dart           URL/ключ Supabase (переопределяются --dart-define), константы
  models.dart           MarkerType (enum, ключ БД, иконка), RoadMarker, MarkerComment
  repo.dart             работа с Supabase: загрузка живых меток, Realtime-подписка,
                        RPC add_marker / vote_marker / add_comment, фильтр типов
  map_screen.dart       главный экран: карта, пины, моя точка, кнопки, режим постановки
  add_marker_panel.dart нижняя панель постановки метки
  marker_sheet.dart     карточка метки (bottom sheet)
  settings_screen.dart  язык, какие типы показывать
  pin.dart              виджет пина
  i18n.dart             строки ru/en/th, timeAgo, тексты ошибок сервера
supabase/schema.sql     таблицы, RLS, функции, Realtime, уборка через pg_cron
android/app/proguard-rules.pro  keep-правила R8 для плагинов
```

### Сервер (supabase/schema.sql)
- Таблицы: `markers` (lat/lng как double, без PostGIS; `expires_at`, `last_confirmed_at`,
  `confirmations`, `denials`, `comments_count`), `votes` (закрыта от клиентов),
  `comments`.
- RLS: `markers` и `comments` читают все; писать напрямую нельзя — только через
  `security definer` функции `add_marker`, `vote_marker`, `add_comment`
  (выданы роли `authenticated`, у `anon` отозваны).
- Ошибки функций — коды в тексте исключения: `too_far:<км>`, `rate_limited`,
  `own_marker`, `already_voted`, `marker_not_found`, `not_authenticated`;
  клиент переводит их в `errorText()` (i18n.dart).
- Realtime: `markers` добавлена в публикацию `supabase_realtime`; клиент слушает
  insert/update/delete и раз в 30 с выкидывает истёкшие метки локально.
- Уборка: pg_cron раз в час удаляет метки, истёкшие больше суток назад.
- Логика проверена на локальном Postgres 16 (все правила выше срабатывают).
  На живом Supabase из среды разработки проверить не удалось (сеть была закрыта).

## Текущий статус

- Код собирается, `flutter analyze` чистый, сборки на GitHub Actions зелёные.
- **Первый запуск релизного APK на эмуляторе упал**: R8 вырезал нативный класс
  `shared_preferences` (`NoSuchMethodError ... SharedPreferencesApiRegistrar.getAll`),
  а инициализация ждала его до `runApp` → вечный сплэш.
  Исправлено (коммит «Починить запуск релизной сборки…»): keep-правила в
  `proguard-rules.pro` + запуск через экран загрузки с показом ошибки.
  **Исправленный APK ещё не проверен на устройстве** — это первое, что нужно сделать.
  Если не поможет: обновить `shared_preferences` или временно отключить минификацию
  (`isMinifyEnabled = false` в release).
- Связка приложение ↔ Supabase вживую ещё ни разу не работала — проверить:
  карта и моя точка, постановка метки, появление метки на втором устройстве онлайн,
  голосование (нужен второй пользователь: другое устройство или переустановка),
  комментарии.
- iOS: папка `ios/` есть, `NSLocationWhenInUseUsageDescription` прописан, но сборка
  под iOS ни разу не запускалась.
